# Technical Design: NSwag Typed API Client

## Overview

Replace the hand-written GameApiClient (raw JSON tuple returns) with an NSwag-generated strongly-typed client. The generated client returns typed DTOs from every method, handles the API response envelope internally, and uses System.Text.Json. A thin hand-written wrapper adds resilience (Polly retry, circuit breaker, rate limiting) and envelope unwrapping. The discovery test tool is migrated to the new client as proof-of-concept.

## Components and Interfaces

### Code Generation Pipeline (tools/nswag-gen/)

A .NET 8 console app that invokes NSwag programmatically (the NSwag CLI crashes on this machine due to CET shadow stack assertion). Located at `tools/nswag-gen/`.

Input: `docs/game-api-swagger.json`
Output: `OE2EmpireTracker.Common/Client/Generated/GameApiGeneratedClient.cs`

```csharp
// tools/nswag-gen/Program.cs (already exists from POC)
var doc = await OpenApiDocument.FromFileAsync(swaggerPath);
var settings = new CSharpClientGeneratorSettings
{
    ClassName = "GameApiGeneratedClient",
    CSharpGeneratorSettings = {
        Namespace = "OE2EmpireTracker.Common.Client.Generated",
        JsonLibrary = CSharpJsonLibrary.SystemTextJson,
    },
    UseBaseUrl = false,
    GenerateClientInterfaces = true,
    GenerateDtoTypes = true,
    OperationNameGenerator = new SingleClientFromOperationIdOperationNameGenerator(),
};
var generator = new CSharpClientGenerator(doc, settings);
File.WriteAllText(outputPath, generator.GenerateFile());
```

Run: `dotnet run --project tools/nswag-gen`

### Generated Client (Common/Client/Generated/GameApiGeneratedClient.cs)

Auto-generated by NSwag. Contains:
- `GameApiGeneratedClient` class with one method per operationId
- All DTO classes (AssetLocations, AssetBlueprint, TokenResponseDto, etc.)
- Returns full envelope types (ServiceResponse_assetBlueprint, etc.)
- Uses System.Text.Json with [JsonPropertyName] attributes
- Accepts HttpClient via constructor injection

Key generated methods:
- `ExchangeTokenAsync(TokenRequestDto body, ct)` → `ServiceResponse_tokenResponseDto`
- `GetAssetsLocationsAsync(appId, search, type, ct)` → `ServiceResponse_assetLocations`
- `GetAssetsLocationDetailAsync(appId, locationId, locationType, ...)` → `ServiceResponse_assetLocationDetail`
- `GetAssetsCrateAsync(appId, crateId, ct)` → `ServiceResponse_assetCrateContents`
- `GetAssetsBlueprintAsync(appId, blueprintId, ct)` → `ServiceResponse_assetBlueprint`
- `GetAssetsSurveyAsync(appId, surveyId, ct)` → `ServiceResponse_assetSurvey`

### Typed Client Wrapper (Common/Client/GameApiTypedClient.cs)

Hand-written thin wrapper around the generated client. Adds:
1. Envelope unwrapping (returns `.Data`, throws on failure)
2. Resilience policies
3. Rate limiting
4. Token management

Note: The wrapper methods hide `X-App-Id` header injection (appId stored at construction), so callers don't pass it per-call.

### Resilience Pipeline (inside GameApiTypedClient)

```csharp
// Built in constructor using Polly 7.2.4
_retryPolicy = Policy
    .Handle<HttpRequestException>()
    .Or<ApiHttpException>(ex => ex.StatusCode >= 500)
    .WaitAndRetryAsync(3, attempt => TimeSpan.FromSeconds(Math.Pow(2, attempt - 1)));

_circuitBreaker = Policy
    .Handle<HttpRequestException>()
    .Or<ApiHttpException>(ex => ex.StatusCode >= 500)
    .CircuitBreakerAsync(3, TimeSpan.FromSeconds(30));

_policyWrap = Policy.WrapAsync(_retryPolicy, _circuitBreaker);
```

### Token Manager (inside GameApiTypedClient)

```csharp
private readonly ConcurrentDictionary<string, CachedToken> _tokenCache;

private async Task<string> GetAccessTokenAsync(CancellationToken ct)
{
    string key = ComputeCacheKey(_clientId, _secret);
    if (_tokenCache.TryGetValue(key, out var cached) && !cached.IsExpired)
        return cached.AccessToken;

    // Token exchange bypasses rate limiter
    var response = await _generatedClient.ExchangeTokenAsync(new TokenRequestDto
    {
        AppId = _appId,
        ClientId = _clientId,
        Secret = _secret,
        GrantType = "client_credentials"
    }, ct);

    var token = response.Data;
    _tokenCache[key] = new CachedToken(token.AccessToken, token.ExpiresIn);
    return token.AccessToken;
}
```

## Error Handling

### Flow

```
HTTP Response
    ├─ 2xx + success=true  → return response.Data as T
    ├─ 2xx + success=false → throw ApiBusinessException(returnCode, returnString, errors)
    ├─ 401                 → throw ApiHttpException(401, body) → caller handles token refresh
    ├─ 429                 → rateLimiter.PauseFor(retryAfter) → throw ApiHttpException(429, body) → Polly retries
    ├─ 5xx                 → throw ApiHttpException(statusCode, body) → Polly retries
    └─ Deserialization failure → throw ApiDeserializationException(statusCode, rawBody)
```

### Polly Retry vs Rate-Limit Distinction

- **Polly retries** handle transient server errors (5xx) and request timeouts. These retry immediately with backoff.
- **HTTP 429** is NOT retried by Polly. Instead, the rate limiter is paused for `Retry-After` seconds, and the request is requeued through the work item system (the discovery tool's queue handles rescheduling).

## Testing Strategy

- Mock `HttpClient` via `HttpMessageHandler` to test envelope unwrapping
- Verify ApiBusinessException thrown on success=false
- Verify ApiHttpException thrown on 4xx/5xx
- Verify rate limiter enforces 0.9 TPS and 9 concurrent
- Verify token cache hit/miss/expiry behavior
- Verify circuit breaker opens after 3 failures

The `GameApiFullDiscoveryTests` fixture validates end-to-end against the real API:
- Authenticates via token exchange
- Crawls all asset locations
- Drills into crates, blueprints, surveys
- Verifies data shapes match generated DTOs
- Runs at 0.9 TPS / 9 inflight
- Produces summary report

## Correctness Properties

### Property 1: Envelope Unwrapping Completeness

**Validates: Requirements 3.1, 3.2**

For any valid API response JSON with success=true, deserializing and unwrapping via the wrapper produces a non-null DTO whose fields match the JSON data payload. Tested by generating random envelope JSON and verifying round-trip.

### Property 2: Rate Limiter Throughput Bound

**Validates: Requirements 6.3, 6.4**

For any sequence of N requests dispatched concurrently, the actual throughput never exceeds 0.5 TPS sustained and never exceeds 30 simultaneous in-flight requests. Tested by recording timestamps of all dispatched requests.

### Property 3: Circuit Breaker State Transition

**Validates: Requirements 6.1, 6.2, 6.6, 6.7**

After 3 consecutive transient failures, IsCircuitOpen returns true and subsequent requests throw immediately without HTTP dispatch. After 30 seconds, a probe request is allowed through.

### Property 4: Token Cache Consistency

**Validates: Requirements 7.2, 7.3**

For any sequence of concurrent API calls, at most one token exchange is in-flight at a time per cache key, and all concurrent callers receive the same token once the exchange completes.

## Design Decisions

| Decision | Rationale |
|---|---|
| Programmatic NSwag (not CLI) | NSwag CLI crashes on this machine (CET shadow stack). Programmatic API via tools/nswag-gen/ works. |
| Hand-written wrapper over generated client | NSwag generates the HTTP transport layer. We add resilience, rate limiting, token management, and envelope unwrapping as a thin layer on top — concerns NSwag doesn't handle. |
| Envelope types generated but hidden | NSwag sees serviceResponse_* schemas and generates them. The wrapper consumes them internally and exposes only the inner data types to callers. |
| System.Text.Json in generated code, Newtonsoft.Json in persistence | Clean boundary: HTTP layer uses STJ, file persistence stays on Newtonsoft. No migration of existing code needed. |
| 0.9 TPS rate limit | Moderately conservative. Well below the API's 300/minute (5 TPS) ceiling but fast enough for practical use. 9 inflight matches the existing queue configuration. |
| Generated code committed to source control | Avoids needing NSwag at build time for regular builds. Regeneration is manual (run tools/nswag-gen when swagger changes). |
| No NSwag.MSBuild for now | The CLI crash means MSBuild integration won't work either. Use the tools/nswag-gen/ console app instead. Update: if the CET issue is resolved in a future .NET update, switch to MSBuild target. |
